## 已实施的修复

| 环节 | 改动 | 目的 |
| --- | --- | --- |
| Range 下载 | JoinSet 管理子请求；父任务取消即终止子任务；首个 64KiB 有效数据复用；200 响应不重发；严格检查范围、声明长度和实际字节；最多一次回退，403/429 不追加回退 | 避免取消后继续占带宽、重复 GET 和错误拼接 |
| 活动会话 | 原始播放列表激活/失活；master、变体和无后缀子清单继承同一会话；旧源 cleanup 按 URL 匹配 | 切源与离开页面时停止旧工作，避免误伤新源 |
| 定位与预取 | 显式定位才变更 seek 代际，正常并行音视频分片不相互取消；同片复用 singleflight；最多一个重后台任务，前台优先 | 减少错误取消与后台竞争 |
| 计数与写盘 | Drop guard 归还下载计数；单线程、有界写盘队列；磁盘命中不重复下载或落盘 | 修复取消泄漏，控制线程和 I/O |
| 移动端与桌面定位 | 横拖、进度条预览接入预取；松手立即提交最终目标；取消、失活、换源精确撤销旧目标；已缓冲定位保留健康加载器 | 缩短热目标恢复，避免松手后误取消 |
| 切集/切视频准备 | 连续缓冲健康后只预热一个候选：下一集优先，否则下一部；实际选流与预热一致；繁忙时低频重试 | 为主播放保留带宽，不并行预热多个视频 |
| 地址与缓冲状态 | 播放地址 Promise 去重、60 秒 TTL；账号/线路变化失效；回切过期地址重取；按真实连续缓冲显示进度 | 避免陈旧地址及缓冲洞误判 |
| HEVC 兼容性 | MSE/native 能力检查；不支持时保留原画质偏好但使用标准流；编码不兼容立即回落，停止无效 recover 循环 | 修复实机切到 HEVC 视频后停在首帧前 |
| 大分片缓存 | 支持单片最多 64MiB，缓存同时限制最多 80 条和总计 192MiB；按 LRU 淘汰；磁盘继续保持单条 8MiB、总计 500MiB | 修复略超 4MiB 分片重复整包下载，同时限制缓存资源 |

主要实现：[媒体调度与缓存](../src-tauri/src/media.rs)、[下载器](../src-tauri/src/net.rs)、[定位控制器](../src/seekPrefetch.ts)、[Feed](../src/components/Feed.tsx)、[VideoSurface](../src/components/VideoSurface.tsx)、[Player](../src/components/Player.tsx)、[API](../src/api.ts)。

## 实际耗时与边界

最终八场景验证使用 WebView2 152.0.4191.66，严格地址校验保持开启，用户缓存未人为清空。下列是单次样本，不是 p95、长期稳定性或修改前后的严格 A/B 测试。

| 场景 | 最终样本 | 计时口径 |
| --- | ---: | --- |
| 已缓冲邻近定位 | 92ms | `web.seek.resumed`：提交定位到恢复渲染 |
| 已访问目标再定位 | 63ms | 同上 |
| 同剧大分片再次回看 | 136.5ms | 点击进度条到 seeked 后实际视频帧 |
| 未缓冲远跳/回看 | 6.267–7.072 秒 | 最终八场景的恢复渲染计时 |
| 同剧 4.2MB 分片首次定位 | 13.772 秒 | 同剧独立复验的点击到实际帧 |
| 下一集 | 8.238 秒 | 点击操作至新源实际出画并继续播放 |
| 下一部视频 | 13.133 秒 | 滚动切换至新源实际出画并继续播放 |
| 离开页面再返回 | 0.599 秒 | 包含失活检查与返回操作 |

**结论：缓存复用、取消正确性、单目标预取与 HEVC 回退已得到验证；冷目标亚秒恢复仍未达标。** 本轮冷加载仍包含完整分片网络传输及播放器恢复，预热被前台繁忙/缓冲不足门槛阻止时，切换仍表现为冷启动。后续若继续优化，应优先做有限量、同目标的下载阶段计时与缓冲策略评估，不扩大并发或用缓存结果掩盖冷加载耗时。

### 实机发现并修复的大分片长尾

[补修前实机报告](../test-results/live-playback/2026-11-12T16-26-10-724Z/report.json) 曾出现 25.255 秒定位。继续比对 [现场日志](../test-results/live-playback/2026-11-12T16-26-10-724Z/playback.log) 发现，资源 `radb193e5` 的同一分片为 **4,207,456 字节**，超过旧 4MiB 上限 13,152 字节。成功下载后未进入缓存，定位期间出现三次 `network.ranged`，并触发 `fragLoadTimeOut` 重试，问题并非全由 CDN 造成。

补修后通过真实应用搜索进入同一剧集 3273 第 1 集，在 35.252 秒定位、跳到另一分片、再回到原目标。该大小的分片网络下载从现场三次变为复验一次，后续回看直接命中。缓存预算测试也验证了大于 4MiB 的 Arc 交接、LRU 字节淘汰、替换条目及超大条目的预算约束。

### HEVC 兼容性现场

用户原 HEVC 偏好为 true；当前 WebView 的 HEVC MSE 探测为 false，AVC 为 true。补修保留用户偏好，但主播放及后台预热共同使用有效选流，UI 显示实际标准画质。浏览器回归另模拟了能力探测通过但编码报错的情况，验证按集回落并停止无效恢复循环。

## 运行和复现

默认 [start.bat](../start.bat) 仍走原来的 `pnpm app:dev`。本机验收时该开发配置重编曾长时间停留；新增可选 `--prebuilt` 模式复用已构建程序，不重复编译 Rust，并先等待 Vite HTTP 就绪再启动桌面进程。关闭桌面窗口后自动停止本次 Vite。

```powershell
# Rust 变更后先编译；保持单 Cargo 并发
$env:CARGO_BUILD_JOBS = '1'
cargo test --manifest-path src-tauri/Cargo.toml --lib -j 1 -- --test-threads=1
cargo build --manifest-path src-tauri/Cargo.toml --bin huangguo-client -j 1
pnpm build
cmd /c "start.bat --prebuilt"
```

```powershell
# 独立浏览器回归：有实际浏览器/视频解码，但业务 API 和媒体来自本地 fixture
node scripts/test-playback.mjs --browser-executable "C:/Program Files/Google/Chrome/Application/chrome.exe"
```

复现真实桌面场景时，在关闭已有实例后，用一个终端临时开启回环 CDP，再从另一个终端运行 [真实验证脚本](../scripts/verify-live-playback.mjs)。脚本默认 9227，校验目标为实际 Tauri 页面，恢复诊断开关，并将结果写入新的时间戳目录。

```powershell

```

```powershell

node scripts/verify-live-playback.mjs --reload
```

结束验证后关闭调试实例，在普通新终端重新运行 `start.bat --prebuilt`。本次交付已经完成此步骤，保留普通运行实例。
